Small, schema-locked language models for the fleet

Harvest a corpus from the repositories, train a tiny transformer, export int8, ship it beside the app. One file per stage, standard library only, no network, no API key.

offline zero dependencies python 3.8+ polyform noncommercial pipeline built · models not trained

The boundary

This kit builds models that turn a sentence into the JSON an app already knows how to use. It does not build chat. A model here is a function with weights: text in, a schema-valid object out, and a refusal when the request does not fit.

The fleet already has both ends. ml-kit is light AI — classic algorithms, no model. The user's own key through sui or ai-bridge is heavy AI. This is the middle.

Nothing here is a diagnostic engine. Mapping case text to rubric identifiers is a retrieval aid. It is not a clinical judgement and must never be presented as one. See DISCLAIMER.md.

What it trained

Same corpus, same shape, same 180 steps, same CPU. Only the tokenizer changes.

The per-token row is a trap: divide by characters per token and BPE is 2.7% better. What it generates is the point.

byte-level  → {"api": "BBdicegi", "auth": "none", "cat": "Bungorincdinaly"
BPE         → {"api": "SDD", "auth": "none", "cat": "Games & Comics",
               "cors": "unknown", "host": "cems..io", "https": "yes"}

The format is learned; the vocabulary is not. That is the correct result for 1.5 M parameters and three CPU minutes, and it is what the 22 M model with a GPU-week closes.

Run it

python3 tools/lm-corpus-harvest.py --root ../src --out ../corpus
python3 tools/lm-bpe.py train --corpus ../corpus --models act --vocab 4096 --bpe bpe-act.json
python3 tools/lm-train.py --corpus ../corpus --model act --out ../run \
        --tokenizer bpe --bpe bpe-act.json --steps 180 --batch 4
